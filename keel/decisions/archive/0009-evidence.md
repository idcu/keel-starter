## 三、被否掉的选项（完整版）

热区只留了最关键的 3 条（自报 / dsh 口径 / 回填入分母），这里补全：

| 选项 | 为什么没选 |
|---|---|
| 直接问 AI"你遵守了吗" | **holaOS 取证已证伪**：门禁全部触发、AI 对 `src/client/` 零编辑、然后宣布完成；加重措辞后更糟。自报不只是不可靠，还会因过于体面而失去诊断价值 |
| 沿用 dsh-rule-lens 的口径（数拦截次数） | 没有分母。加载 10 条违反 1 条 → 拦截 0 次 → 读起来像 100% 遵守。**数字方向是反的**，比没有数字更危险 |
| 让 AI 自报"Self-Review"（aegis 的做法） | 把度量权交给被度量者 |
| 靠 MCP 记录 AI 读了什么来推断遵守 | 读到 ≠ 照做。加载量已在 §7 管住，不构成新信息 |
| 把回填轮次计入遵守率分母 | 分母不存在。能立刻让数字"有基线"，但那个基线是假的 |
| 用假项目造数据当基线 | 项目已明确"假项目只验机制，不可当成绩"（CHANGELOG 3.3.0） |
| 干脆不做回填，让用户等几周 | **新用户装完第一天看不到任何数**——而那正是决定他会不会继续用的一小时 |
| 回填时用各历史提交自带的 lint / budget.env | 判据随版本漂移，跨提交不可比。故统一用**当前判据**重放历史内容 |
| 把回填结果直接叫"遵守率" | 名字一旦借用，所有人都会拿它当遵守率读——而它量的是另一件事 |
| 靠"写得更明确更详细"减少违规 | holaOS 取证已证伪：加重措辞反向优化，得到更精致的形式合规 |
| 让 AI 自检后再写回 | 自报不可靠；且 §2 原则 4：靠自觉的不算规则 |
| 只在 CI 校验，不挂 pre-commit | 太晚——违规内容已进历史，而历史**不可重建** |
| 放宽判据让内容能通过 | **判据放宽等于把过去的 fail 变成沉默**（§2 原则 4 + 人审关卡） |

## 四、回填的已知失效模式

回填是"机器造数"的路径，错了不报错，只给一个**看起来很像真的假数字**。
已登记三条同形状的坑：

- `worktree-eol-differs-from-main` —— worktree 与主树EOL 不同，报 27 条假孤儿
- `submodule-pointer-drift-not-machine-checked` —— 两仓全绿但指针有 `+`
- lint 目录入参传绝对路径 —— 复核传绝对路径致 16 条假 fail

**共同形状：静默产出错误数字。** 这是度量类工具最危险的失效模式——
数字看起来完全合理，不检查就永远发现不了。

## 五、外部证据

**arXiv 2606.15828（UFMG）**——解剖 GitHub Top-100 仓库：**91% 至少含一种配置异味**，
其中 Lint Leakage 62% / Context Bloat 42% / Skill Leakage 35%。
Lint Leakage 指**把 lint 本可判死的规则抄进说明书**，用自然语言做机器该做的事。
这是 ADR 0012（现0009 第四节）的直接依据。

**arXiv 2602.11988（ETH Zurich，ICML 在审）**——LLM 生成 AGENTS.md 降成功率约 3%、
成本 +20~23%。与 2601.20404（时间 −28.64%、token −16.58%）共同结论是**「最小化」**，
对 Keel 反而有利：它印证"手写 + 精简"优于"生成 + 详尽"。
