# 0011 历史提交可以回填，但回填出来的**不是遵守率**

> 口径正文在设计稿 §11.2；本 ADR 只留"为什么这么定"与被否掉的选项。

## 背景

遵守率唯一的硬伤是**没有基线**：它从装上 pre-commit 那一刻才产生数据，
要等几周才有意义。于是很自然会想到——**用 git 历史回填，把基线造出来**。

技术上做得到：lint 是纯 bash，可以对任意历史提交重放。

## 决定

**回填做，但它产出的是另一个数：存量合规率。它不进遵守率的分母。**

理由只有一句：**遵守率的分母是"门禁有机会拦的次数"，
装上钩子之前的历史提交根本没有门禁——分母不存在，回填造不出分母。**
把它们算进分母，等于宣称"这些提交当年被检查过"，那是伪造客观事实，
正好违反 ADR 0009 的立身之本。

所以在 `violations.jsonl` 里回填记录带 `backfill=1`，
聚合时与 `baseline` 一样被排除出主分母，只在报告里单列一段：

```
存量合规率 = 1 − 命中提交数 / 被回填的历史提交数
```

它回答的问题与遵守率不同：**「仓库现存的内容，按今天的判据看有多干净」**。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 把回填轮次计入遵守率分母 | 上面那句：分母不存在。这么做能立刻让数字"有基线"，但那个基线是假的 |
| 用假项目造数据当基线 | 项目已明确"假项目只验机制，不可当成绩"（CHANGELOG 3.3.0） |
| 干脆不做回填，让用户等几周 | **新用户装完第一天看不到任何数**——而那正是决定他会不会继续用的一小时 |
| 回填时用各历史提交自带的 lint / budget.env | 判据随版本漂移，跨提交的数字不可比。故统一用**当前判据**重放历史内容 |
| 把回填结果直接叫"遵守率" | 名字一旦借用，所有人都会拿它当遵守率读——而它量的是另一件事 |

## 后果

- **好处**：新用户装完就能看到第一个数；存量合规率也给遵守率提供了对照物
  （若实时遵守率显著低于存量合规率，说明 AI 在制造**新的**不合规，而不是历史欠账）。
- **代价 1**：在**已经接入 Keel 的仓库**里，它会接近 100%——存量早被门禁筛过一遍，
  此时这个数信息量很低。它真正的用武之地是"刚装完、历史从未被门禁管过"的仓库。
- **代价 2**：每个历史提交跑一次完整 lint，默认 `--max 10`；大仓库要自己调，别一次全量。
- **新增一类失效模式**（已登记为坑）：临时 worktree 的行尾与主工作树不一致 →
  字节虚高 + 链接解析失败 → **批量假 fail**；lint 的目录入参传绝对路径同样会造成假 fail。
  **回填这种"机器造数"的路径，错了不会报错，只会给出一个看起来很像真的假数字。**
