# 0009 遵守率：口径、数据源，以及什么不算遵守率

> 口径公式正文在设计稿 §11.2；完整取证与被否选项见
> `archive/0009-evidence.md`（冷区）；实时数字用 `keel/checks/compliance.sh report` 查。
> **热区只留决策要点**——§7.3「沉」，细节不占预算（§2 原则 1）。
>
> **v3.4.5 由原 0009 + 0011 + 0012 合并**：三篇讲同一条线——「什么算分母」，
> 各自成篇，检索"分母"会同时命中 3 篇重文档（实测命中 17,040 字节，
> 加必读 5,021 = 22,061，超 §7.2 预算 36%）。内容一条没丢，只是从三份变一份。

## 一、为什么要有这个指标

§11 的三个度量（返工率 / 坑复发率 / 平均阻塞时长）全部度量**项目**，
没有一个度量 **AI 本身**——它到底有没有真的遵守规则。而这是整套系统的最终目的：
Keel 的意义是"让 AI 以恒定成本拿到正确上下文**并照做**"，拿到却不照做，前三个数再好也说明不了问题。

2026-10 逐个**读源码**核实（非读 README）：14 行竞品表里"有分母的遵守率"**0 个**。
最像的两个都栽在同一处——dsh-rule-lens 只数拦截无分母（语义反向），
aegis 让 AI 自报（不可验）。取证见冷区。**空白是真的。**

## 二、口径与数据源

**遵守率 = 1 − (lint 命中轮次 + 放行后被回滚数) / 总检查轮次**
（初版只算前者，v3.3.1 修正——见第六节）

数据源全客观，**均不来自 AI 的输出**：`violations.jsonl`（pre-commit 写）、
`load.jsonl`（load-estimate 写），回滚数读 `git log --grep=^'Revert "'`。
**所以 AI 一个都改不了。**

## 三、历史回填不进分母

**决定：回填做，但它产出的是另一个数：存量合规率，不进遵守率的分母。**

理由只有一句：**分母是"门禁有机会拦的次数"。装上钩子之前的历史提交根本没有门禁——
分母不存在，回填造不出分母。** 算进去等于宣称"这些提交当年被检查过"，那是伪造客观事实，
正好违反第二节的立身之本。回填记录带 `backfill=1`，聚合时排除出主分母，单列：

```
存量合规率 = 1 − 命中提交数 / 被回填的历史提交数
```

它回答另一个问题：**「现存内容，按今天的判据看有多干净」**。

## 四、写回必须过门禁才算数

**决定：任何进入热区的写回内容，必须能被 `keel-lint.sh` 判死；判不死的写法不许进热区。**

推论：① 写回走 pre-commit 钩子，不是"建议"；② **"写得清楚"不能替代"判得死"**——
判据是 lint，不是读者的理解力；③ 判不死的真内容沉冷区，热区只留一行指针。

外部证据（arXiv 2606.15828 解剖 GitHub Top-100）：**91% 至少含一种配置异味，
其中 Lint Leakage 占 62%**——把 lint 本可判死的规则抄进说明书。
**"写了规则"和"规则被机器执行"是两件事**，主流做法普遍只做了前者。

## 五、关键代价与风险

- 只能测"可被脚本判死"的规则。这**逼着人把规则写成可判死的**，是好事，
  但一开始会暴露一批"假规则"（**暴露存量问题，不是新增问题**）。
- **没有真实用户数据**，遵守率会长期是空序列。没基线的指标最容易变成自欺欺人的数字
  ——所以本篇只定口径，**不承诺何时给出真实数字**。
- 存量合规率在已接入 Keel 的仓库里会接近 100%（存量早被门禁筛过），信息量低；
  用武之地是"刚装完"的仓库。
- 回填是"机器造数"的路径，错了不报错，只给一个**看起来很像真的假数字**。
  已登记三条同形状的坑（静默产出错误数字）。
- 判据只覆盖可判死的规则；措辞、语气、示例质量**仍依赖人的判断**，本篇不声称解决了它。

## 六、沉淀

**其一：点名失败模式，AI 就精确复现它。** 写"不要犯 X"反而提高犯 X 的概率。
故坑条目「正解」段必须写具体动作，不能只写"不要那样做"——这不是文风，是有效性。

**其二（本项目两次自曝）：**① v3.3.1 初版漏了「放行后被回滚的提交」——
那是 lint 自己看不见的一类不遵守，修正后同一假仓遵守率 66.7% → 33.3%（**虚高一倍**）。
② v3.4.5 实测 ADR 0010 立的 CI 检查只在发布仓、两周无人查看，
`keel-version` 已到 3.4.4 而 CHANGELOG 停在 3.4.2。**判据存在却没人看 = 没有判据。**
故新增 lint 第 17 项。
