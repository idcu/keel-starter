# 0004 孤儿判定改为"真实链接图"，不再按文件名字符串匹配

## 背景

v3 的孤儿检测（§9.1-4）实现是 `grep -qF "$base" "$corpus"`——把热区正文拼成一个语料，
再看文件名有没有"出现在里面"。这是**近似算法**，两头都会错：

- **漏报**：正文里偶然写到 `orphan.md` 这个词（哪怕不是链接），该文件就被当成"被引用"；
- **误报**：文件改名后，旧名字仍在别处残留，或名字是常见词（`setup.md`），匹配到不相关文本。

而孤儿的失效模式恰恰是项目变大后最致命的那一个：**文件还在，但没有任何入口指向它**。

## 决定

孤儿 = 热区文档中，**没有任何热区文档通过链接指向它**。
判定改为真实链接图：把每条 markdown 链接与 `@路径` 引用，相对所在文件目录解析成目标文件的绝对路径，
放进"被引用集合"，再逐个文档查自己是否在集合里（`INDEX.md` 与 `_template*` 照旧豁免）。

> 顺带一个自己的教训：本文初稿里写了 `]（路径）` 的字面形态作示例，被 lint 当场判成死链——
> **文档里写"链接语法"的示例，本身就是一个真链接**。这正是 §9"机器验"该有的样子。

## 被否掉的选项

| 选项 | 为什么没选 |
|---|---|
| 保留文件名 grep，只加"必须带 `](`" | 仍然不解析相对路径；同名文件、跨目录引用一律判错 |
| 用 markdown 解析库做完整 AST 引用图 | 内核要保住 bash 3.2 / awk / sed / find 的零依赖底线（§9.3） |
| 干脆去掉孤儿检查（误报烦人） | 去掉的正是"文件一多就再也找不到"的唯一防线 |

## 后果

- 好处：判定与 §9.1-3 死链检查同源（都解析真实路径），两处口径终于一致；正文提及不再算引用。
- 代价：**存量仓库可能新报孤儿**——此前靠"正文里提过名字"蒙混过关的文件会被揪出来，
  须在 `INDEX.md` 路由表或所在域索引里补一行真链接（这正是检查想要的）。
- 回归护栏：新增用例 37（正文提及但无链接 → 仍判孤儿），专门钉住这个语义。
