# ARCHITECTURE

> **只画现状，不写愿望**：这里写"现在是什么样"，不是"希望变成什么样"——愿望写在
> `CONSTITUTION.md` 的身份段。改了模块边界或依赖方向，等于改了红线，走人审关卡。
> 规格见《Keel 设计稿》§5.3。

## 模块

| 模块 | 一句话职责 | 目录 | owner |
|---|---|---|---|
| <api> | <对外入口> | `<src/api/>` | <谁> |
| <domain> | <业务规则> | `<src/domain/>` | <谁> |
| <infra> | <存储 / 外部服务> | `<src/infra/>` | <谁> |

## 依赖方向

| 从 ↓ 到 → | api | domain | infra |
|---|---|---|---|
| **api** | — | ✅ | ❌ |
| **domain** | ❌ | — | ✅ |
| **infra** | ❌ | ❌ | — |

## 关键数据流

只写真正重要的 1–3 条，格式「入口 → 经过 → 落点」：

1. `<POST /orders → api → domain.OrderService → infra.OrderRepo → DB>`
2. `<定时任务 → ...>`

## 契约

契约（API / 类型 / 事件）的**唯一真源是 `contracts/`**。本文件只描述边界与方向，
不复制任何字段定义——能引用的绝不复制，否则必然漂移（§2 原则 1）。
